# 管理安全設定與安全影響

## 具安全影響的行政職務

Adobe Learning Manager 採用基於角色的存取控制（RBAC）模型。 下表將 FedRAMP 帳戶層級對應至本文件中提及的 ALM 角色：

| 聯邦RAMP條款 | ALM 角色 | 安全相關性 |
|-------------|---------|------------------|
| 頂層行政帳號 | 行政長官 | 完全的帳號層級控制。 獨家存取本文件中描述的所有安全相關設定。 本指南中提及的「頂層行政帳戶」角色即為此。 |
| 特權帳戶（範圍） | 自訂管理員 | 授權的管理權限可涵蓋特定功能、使用者群組或目錄。 除非明確授權，否則無法存取帳號層級的安全設定。 |
| 特權帳號（整合） | 整合管理員 | 管理整合、API 註冊及連接器配置。 權限提升至整合管理。 無法修改其他帳號層級的安全設定。 |

>[!NOTE]
>
>只有明確指派這些角色的使用者才能修改管理或與安全相關的設定。 第3至7節所記錄的設定，除非另有說明，僅供管理員角色使用。

## 登入與驗證設定

登入與驗證設定控制所有使用者——包括管理員——如何存取 ALM 平台。 這些設定完全由管理員角色設定，對整個帳號的安全狀態有直接且重大的影響。

### 登入方式設定

**地點：** ALM 管理員 > 設定 > 登入方法

管理員負責所有內部及外部使用者所使用的認證方式。 選項包括：

- **Adobe ID：** 使用者透過個人 Adobe 帳號進行認證。 由 Adobe 管理，不是組織本身。
- **透過 SAML 2.0** 進行單一登入（SSO）：使用者透過組織的身份提供者（IdP）進行認證。 該組織完全掌控認證、多因素驗證（MFA）及會話政策。
- **學習管理員 ID：** 僅限外部使用者使用。 使用者建立平台專屬的使用者名稱和密碼。
- **多重 SSO 配置：** 最多可新增 20 種 SSO 配置，以支援不同的使用者群組、地點或組織部門

| 登入方式 | 安全影響 | 推薦 |
|-------------|---------------------|----------------|
| **Adobe ID** | 組織無法控制密碼政策、多重驗證或帳號恢復。 一個被入侵的個人 Adobe 帳號會讓使用者存取 ALM 平台。 | **不建議給管理員或內部使用者使用** 。 僅在無法使用 SSO 時使用。 |
| **SSO（SAML 2.0 / 聯邦識別碼）** | 認證完全由組織的 IdP 控制。 多重認證（MFA）、會話逾時及條件存取政策皆在 IdP 層級強制執行。 用戶離開時立即撤銷。 | **推薦** 給所有內部使用者與管理員使用。 提供最高層級的組織控制。 |
| **學習管理器識別碼** | 使用者在組織的身份基礎設施之外自行管理密碼。 無法透過 ALM 強制執行 MFA。 密碼強度取決於使用者行為。 | 僅限外部使用者使用。 不適合員工或行政人員。 |

>[!CAUTION]
>
>若內部使用者登入方式設為 Adobe ID，組織將失去強制多重身份驗證、控制密碼複雜度或在使用者離開時立即撤銷存取權限的能力。 這大幅增加了未經授權存取的風險。

更多資訊請參見 [自訂角色](https://experienceleague.adobe.com/en/docs/learning-manager/using/admin/custom-role) 。

### 多重身份驗證（MFA）

**地點：** Adobe 管理控制台 > 隱私與安全設定> >認證設定

Adobe ID 與企業識別&#x200B;**碼使用者的多重驗證強制執行**&#x200B;由系統管理員&#x200B;**在 Adobe 管理控制台中設定**，而非在 ALM 應用程式本身。****&#x200B;對於 **聯邦身份證/SSO** 使用者，MFA 會在組織的身份提供者處強制執行。

- **強制雙重驗證：** 使用者無法關閉兩步驟驗證。 提供強力防範憑證盜竊與網路釣魚的防護。
- **可選的雙重驗證：** 使用者可選擇是否啟用兩步驟驗證。 安全防護明顯較弱。
- **未設定多重身份驗證（MFA）：** 僅靠密碼就能保護存取權限。 高風險，尤其是行政帳戶。

>[!IMPORTANT]
>
>未強制多重認證的管理帳號面臨更高風險，未授權存取的風險顯著較高。 未經多重驗證的管理員憑證被盜，將獲得完整的帳號控制權，包括修改所有安全設定的能力。

### 會話生命與閒置暫停

**地點：** Adobe 管理主控台 > 隱私與安全設定 > >進階設定

**系統管理員**&#x200B;負責設定組織的最大活動會話壽命及閒置會話逾時。這些設定適用於所有使用者，包括管理員。

- **最大會話壽命：** 無論活動如何，在限定期限後強制重新認證。 如果會話被破壞，這會限制機會窗口。
- **最大閒置時間：** 終止已非活躍一段時間的會話。 防止共享或解鎖裝置上的無人值守認證會話。

## 角色指派與權限範圍設定

角色指派與權限範圍設定決定誰擁有 ALM 中的管理員權限及其能做的事。 這些是平台上最具影響力的安全設定之一。 只有管理員角色能建立、指派、修改或撤銷管理員角色。

### 行政職務分配

**地點：** ALM 管理員>使用者>內部>動作>指派角色/移除角色

**管理員**&#x200B;可授予或撤銷以下職務：

- **管理員：** 完整帳號層級存取權
- **作者：** 內容創作權限
- **自訂管理員：** 有範圍的管理存取權（見第 4.2 節）
- **整合管理員：** 整合與 API 存取權限（見第 7 節）

| 背景/動作 | 安全影響 | 建議做法 |
|---|---|---|
| **授予管理員角色** | 完全控制帳號。 擁有此角色的使用者可修改本文件中的所有設定，包括重新設定認證及撤銷其他管理員的存取權限。 | 只指派給具備驗證業務需求的最低用戶數量。 維護所有管理員角色持有人的文件清單。 |
| **離職時未能撤銷職務** | 離職的使用者仍可存取管理功能。 有未經授權存取、資料外洩或破壞的風險。 | 當使用者的工作或行政職責改變時，立即移除角色。 定期進行存取審查。 |
| **過度分配廣泛的角色** | 廣泛的行政存取增加了帳號被入侵的潛在影響，並降低了對行政行為的問責。 | 應用最小特權原則。 盡可能偏好有範圍的角色（例如自訂管理員）。 |

### Custom Administrative Role Configuraton

**地點：** ALM 管理員>使用者>自訂角色>建立角色

應用最小特權&#x200B;**原則**。使用 **自訂管理員** 角色來委派特定功能（見第 4.2 節）。

**管理員**&#x200B;可以建立自訂角色，授予定義的管理權限子集。自訂角色可限定於特定使用者群組、目錄或功能集，限制授權管理權限的範圍。

**可用的權限類別包括：**

- **帳號權限：** 可存取系統範圍的設定，如公告、遊戲化、技能管理及使用者管理。
- **功能特權（核心）：** 存取目錄、報告及標籤。
- **功能權限（學習對象）：** 可取得課程、認證、學習路徑及工作輔助工具。
- **範圍：** 將角色限制於特定的使用者群組和/或目錄。

| 配置決策 | 安全影響 | 建議做法 |
|---|---|---|
| **建立過於廣泛的自訂角色** | 擁有過多權限的自訂角色，安全性提升有限，且會增加被入侵帳號的攻擊範圍。 | 將自訂角色範圍設為該功能所需的最低權限集。 偏好以目錄範圍和使用者群組範圍的角色。 |
| **授權設定存取權給自訂管理員** | 擁有設定權限的自訂管理員可以修改登入方式、通知設定及其他帳號層級設定。 | 只有在明確需要時才會授權設定存取自訂角色。 定期審核哪些自訂角色擁有此權限。 |
| **不審核自訂角色分配** | 未經文件化或未經審核的自訂角色可能會隨時間累積，導致權限膨脹。 | 定期下載自訂角色報告（**使用者>自訂角色>下載**），並檢視所有有效的自訂角色分配。 |

## 使用者配置與存取管理設定

使用者配置設定控制使用者如何被加入平台、保持活躍時間，以及何時移除資料。 這些設定僅由管理員角色設定，對資料外洩與存取控制有直接的安全影響。

| 背景設定 | 位置 | 安全影響 | 推薦預設 |
|---|---|---|---|
| **非活躍使用者自動刪除** | ALM 管理員>設定>一般 | 沒有自動刪除，非活躍帳號會累積。 休眠帳號是未經授權存取的常見目標，因為它們可能未被監控。 | 啟用。 設定與組織政策相符的留任期（例如，90天不活躍）。 |
| **外部使用者設定檔到期** | ALM 管理員>使用者>外部>新增設定檔 | 沒有過期期限的外部使用者檔案仍可無限期存取。 不再需要存取的合作夥伴或承包商仍保留有效的入口點。 | 在建立時為每個外部使用者設定一個有效期限。 |
| **自我註冊連結控制** | ALM 管理員>使用者>內部>新增>自我註冊功能 | 自助註冊連結允許任何擁有該網址的使用者建立學習者帳號。 若未加以管理，可能導致未經授權或意外的使用者取得平台存取權。 | 僅在需要時產生自助註冊連結。 請立即停用或撤銷未使用的連結。 |
| **外部檔案暫停/履歷** | ALM 管理員>使用者>外部>動作>暫停 | 暫停外部設定檔會阻止新用戶註冊，但不會影響已註冊的用戶。 未暫停非啟用的外部設定檔可能會造成非預期註冊。 | 當不再需要註冊時，請暫停外部設定檔。 刪除永久不活躍的個人檔案。 |
| **使用者刪除與清除** | ALM 管理員>使用者>內部>操作>刪除/使用者清理>清除 | 被刪除的使用者會被停用，但其資料會被保留。 清除會永久移除所有使用者資料。 未清除離職使用者可能會在超過規定保留期限後保留敏感的學習紀錄與個人識別資訊（PII）。 | 依照組織資料保存與隱私政策清除使用者紀錄。 清除是不可逆的。 |

>[!IMPORTANT]
>
>清除是永久且不可逆的。 所有學習紀錄、註冊資料及使用者資訊均被刪除。 若在連接器配置中被提及被清除的使用者，該連接器將被停用。 執行清除前務必仔細確認選擇。

## 報告與資料存取設定

報告與資料存取設定決定哪些使用者可以瀏覽、產生及匯出平台資料。 這些設定的錯誤設定可能導致敏感的個人、組織或合規相關資訊外洩。

| 背景設定 | 位置 | 安全影響 | 推薦預設 |
|---|---|---|---|
| **授權報告存取自訂角色** | ALM 管理員>使用者>自訂角色>功能權限>報告 | 報告可能包含個人識別資訊（PII）、課程完成資料、評量分數及學習進度。 報告功能的存取應限制於具備經驗證業務需求的使用者。 | 補助報告僅能存取有特定且有文件需求的職位。 在不需要寫入權限時，請使用唯讀存取。 |
| **完全控制與唯讀報告範圍** | ALM 管理員>使用者>自訂角色>帳戶摘要報告 | 對帳戶摘要報告的完全控制權賦予所有使用者群組與目錄的自訂管理員可見性，無論其角色範圍為何。 這可能會暴露超出有範圍管理員角色預期範圍的資料。 | 僅授予真正需要全組織報告可見性的角色，全面控制帳戶摘要報告。 |
| **xAPI 與電子郵件報告存取權限** | ALM 管理員>使用者>自訂角色 | xAPI 報告與電子郵件報告僅提供給完整管理員角色。 這些報告可能包含詳細的行為與溝通資料。 進入是設計上的限制。 | 不要嘗試透過自訂角色委派 xAPI 或電子郵件回報存取權限。 這些設計上是管理員專用的。 |
| **匯出使用者資料** | ALM 管理員>使用者>內部>匯出使用者資料 | 匯出使用者資料功能會產生包含所有內部使用者紀錄的可下載檔案。 這些資料必須依照組織的安全與隱私政策進行處理。 | 限制出口能力僅限授權人員。 將匯出資料視為敏感資料。 請勿儲存或傳送該資料於核准系統之外。 |

## 整合與 API 存取設定

整合與 API 存取設定控制外部系統如何連接 Adobe Learning Manager。 這些設定將存取權限擴展至ALM使用者介面之外，若設定錯誤，可能會將平台資料與功能暴露給未經授權的系統。  整合設定由整合管理員角色管理。 完整的管理員角色仍保留審查、核准及撤銷已註冊申請的能力。

| 背景設定 | 位置 | 安全影響 | 推薦預設 |
|---|---|---|---|
| **API 應用程式註冊** | Integration Admin > Applications > Register | 註冊應用程式會產生 OAuth 2.0 憑證（用戶端 ID 與秘密），可用來程式化存取 ALM 資料與功能。 過於寬泛的 OAuth 範圍（例如管理員角色讀寫）會授予完整的管理 API 存取權限。 | 授予最低要求的OAuth範圍。 定期審查並撤銷未使用或舊有的申請註冊。 把客戶端憑證當作敏感機密來處理。 |
| **OAuth 應用範圍** | Integration Admin > Applications > Register > Scopes | 可用的 OAuth 範圍從學習者讀取權限到管理員讀寫權限皆有。 管理員角色讀寫允許應用程式修改管理員可修改的任何資料，包括使用者角色與安全設定。 | 使用符合整合要求的最嚴格 OAuth 範圍。 除非絕對必要，否則絕不要授予管理員角色讀寫權限。 |
| **連接器配置（FTP、Salesforce、HRIS 等）** | 整合管理 >連接器 | 連接器可自動匯入與匯出使用者資料、技能及課程完成紀錄。 錯誤配置的連接器可能匯入錯誤的使用者資料、指派非預期的角色，或將敏感資料匯出至未經授權的目的地。 | 定期檢查所有主動接頭配置。 確保資料來源和目的地都獲得授權。 停用不再使用的連接器。 |
| **Webhook 配置** | 整合管理 > Webhooks | Webhook 會即時將 ALM 事件資料（註冊、完成、使用者變更）傳送到指定的外部 URL。 設定錯誤或被入侵的 webhook 端點可能導致資料外洩或敏感學習者事件的暴露。 | 僅註冊經過驗證、經組織核准的 webhook 網址。 定期檢視主動式 webhook 配置。 立即移除不活躍或未識別的 webhook。 |
| **LTI 整合配置** | 整合管理 > LTI 整合 | LTI 整合讓 ALM 能作為 LTI 提供者或消費者，使外部 LMS 平台能存取 ALM 課程。 一旦啟用，LTI 就無法被關閉。 暴露的LTI憑證可能會允許未經授權存取課程內容。 | 只有在有經過驗證的整合需求時才啟用 LTI。 將LTI憑證視為敏感資料。 僅與授權的 LMS 管理員共享憑證。 |

## 行政配置責任與共同責任

Adobe Learning Manager 中的管理設定可由客戶配置，並屬於 Adobe 共同責任模式下由客戶管理的安全控制系統。

| Adobe 職責 | 客戶責任 |
|---|---|
| ALM 平台及底層基礎設施的安全運作。 | 所有管理角色與權限的設定。 |
| 執行基於角色的存取控制（RBAC）模型。 | 選擇並執行適當的登入方式與多重身份驗證（MFA）。 |
