# 管理員稽核追蹤報告 {#adminaudittrailreport}

產生一份關於你帳戶基礎、進階及整合設定變更的報告——包括是誰、何時、前後的設定變更。

## 報告所捕捉的內容

管理員稽核追蹤報告會提供設定變更的歷史紀錄，讓你能判斷：

- 是誰做了改變
- 變更的時刻
- 改名前的設定是什麼
- 改版後的設定是什麼

報告涵蓋了以下方面的變更：

- **基本** 設定
- **進階** 設定
- **整合設定**

報告僅為加法：新變更紀錄會隨時間新增，且先前記錄的項目永遠不會被刪除。 這讓你能檢視設定在多次變更中的完整歷史，而不只是目前的數值。

該報告對任何擁有舉報權限及完整使用者群組存取權的使用者開放。 這包括已獲得報告權限的正式管理員及自訂管理員。

>[!NOTE]
>
>紀錄自 2026 年 9 月第 112 次更新開始可查閱。 本次更新前所做的變更未包含在報告中。 詳見 [發行說明](/help/migrated/release-note/release-notes.md) Update 112。

## 為何本報告對合規至關重要

在受管制產業運作的組織，通常需要證明處理電子紀錄系統的配置變更被追蹤、歸因並被保留。 管理員稽核追蹤報告透過識別每次變更的人員、設定、時間及前後數值來支持這些要求。

>[!NOTE]
>
>此報告支持貴組織的合規活動。 它本身並不證明符合任何特定法規或標準。

## 產生管理員稽核追蹤報告

1. 以管理員身份登入 Adobe Learning Manager。
2. 在左側導覽中，選擇 **管理** > **報告** > **自訂報告**。

   ![](/help/migrated/administrators/feature-summary/assets/audit-trail-report1.png)

3. 往下滑，選擇 **管理員稽核追蹤**。

   ![](/help/migrated/administrators/feature-summary/assets/audit-trail-report2.png)

4. **選擇範圍**：選擇要報告的期間—— **過去一週**、 **過去一個月**&#x200B;或 **選擇日期**。 選擇 **「選擇日期**」時，請輸入 **「發件** 日期」和「 **到日期** 」。
5. **選擇設定類型**：選擇&#x200B;**全部**、**基礎、**&#x200B;**整合或**&#x200B;**進階**。

   若要查看本報告追蹤的基礎、整合及進階完整設定清單，請選擇 **「下載設定**&#x200B;清單」。

   ![](/help/migrated/administrators/feature-summary/assets/audit-trail-report6.png)

   ![](/help/migrated/administrators/feature-summary/assets/audit-trail-report3.png)

6. 選擇 **產生**。

   ![](/help/migrated/administrators/feature-summary/assets/audit-trail-report4.png)

   ![](/help/migrated/administrators/feature-summary/assets/audit-trail-report5.png)

`.csv`包含變更的檔案會下載到瀏覽器的 Downloads 資料夾。報告產生可能需要幾分鐘——你可以在處理時繼續使用 Adobe Learning Manager。 如果您在報告尚未準備好前關閉瀏覽器視窗，下載將從下一次登入時開始。

## 本報告的常見用途

- **調查突發的設定變更** ——確認是什麼、何時、誰改變了，而不是依賴假設。
- **檢視多位管理員** 所做的變更——產生報告範圍內特定期間內所有組態活動的整合檢視，而非逐一聯絡每位管理員。
- **確認已核准的設定變更** ——確認預期管理員在預期時間內完成變更，且新值是否符合核准。
- **比較設定在多次變更** 中的歷史——使用 **修訂** 欄查看特定設定變更了多少次，並依序檢視每個記錄值，包括後續變更是否恢復了先前的值。
- **支持合規審查** ——將該期間的報告產生，作為您的行政及合規紀錄的一部分。
- **政策變更** 後檢視設定——確認預期的設定更新是否持續套用，並找出任何意外發生的變更。
- **維護歷史行政紀錄** ——依照貴組織的紀錄管理做法下載並保存報告。

## 報告欄參考

下載的 `.csv` 檔案包含以下欄位。

| 柱狀 | 說明 |
|---|---|
| **事件識別碼** | 此變更記錄的唯一識別碼。 |
| **時間戳記（UTC）** | 變更的日期和時間，是協調世界時。 |
| **電子郵件** | 是更改管理員的電子郵件地址。 |
| **UUID** | 一個唯一識別碼，代表負責更改的管理員。 只有在帳號層級啟用 UUID 時才會被填入。 |
| **管理員名稱** | 是更改管理員的顯示名稱。 |
| **事件類型** | 所記錄的事件類別——例如 `Modify`、、 `Create`或 `Delete`。 |
| **動作類型** | 在設定上執行的動作類型——例如， `CREATE_SETTING`、、 `UPDATE_SETTING`或 `DELETE_SETTING`。 |
| **物件類型** | 被更改的設定或設定物件。 |
| **物件識別碼** | 該設定或設定物件的唯一識別碼。 |
| **先前價值** | 設定在改變前的價值。 （對於刪除設定，這顯示刪除前存在的值。） |
| **新價值** | 設定在改變後的價值。 （刪除設定為空白。） |
| **修訂版** | 當事件被記錄時，這個特定物件 ID 被更改的次數。 物體首次記錄的變化從1開始。 |

>[!TIP]
>
>要找到某段期間內刪除的所有設定，請篩選下載檔案中動作&#x200B;**類型**。`DELETE_SETTING`

## 以程式化方式存取本報告

你可以透過 Jobs API 程式化取得管理員稽核追蹤報告，而不必從 Admin 應用程式手動產生。 如果你想排程定期匯出或將報告輸入下游監控或警示系統，這很有用。 請參閱 [職缺API管理員稽核報告](/help/migrated/api-changes-sep-2026.md#job-api-for-admin-audit-trail-report)。

## 限制

- **在地化**：舉報內容未具備在地化。 報告會以預設帳戶語言產生，無論你帳戶的地點設定如何。
- **變更**&#x200B;原因：報告未說明變更的原因。 任何相關的變更請求、核准或業務理由，請另行保存。

## 最佳實務

- 選擇涵蓋預期或計畫變更的日期範圍。
- 當受影響的設定區域未知時，選擇&#x200B;**「全部選擇」。**
- 請比較 **每個條目的「先前值** 」與 **「新值** 」欄位。
- 使用 **管理員姓名** 和 **時間戳** 欄位，將變更與已核准的工作或內部紀錄關聯起來。
- 當組織需要文件說明變更時，請將相關的變更請求、核准或業務理由分開保存。

## 疑難排解

**我沒看到任何在某個日期之前的紀錄**&#x200B;紀錄僅自第 112 次更新（2026 年 9 月）起提供。 更新前所做的變更不包含在報告中。 詳見 [發行說明](/help/migrated/release-note/release-notes.md)

**UUID 欄位對部分或全部紀錄為空**&#x200B;只有當帳號層級啟用 UUID 時，UUID 欄位才會被填入。 若未啟用，該欄位將不存在。

**我有一個自訂的管理員角色，但我找不到這個報告**&#x200B;確認你的自訂角色已被賦予舉報權限及完整使用者群組存取權。 如有需要，請聯絡您的帳號擁有人或正式管理員申請此權限。
