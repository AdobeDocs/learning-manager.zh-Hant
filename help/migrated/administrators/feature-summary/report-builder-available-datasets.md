# 報告建構器中可用的資料集

## 概觀

報表建立器將所有可用欄位組織成資料集，並以相關欄位的命名群組命名。 本文列出每個資料集，說明其內容，並指出哪些資料集可以合併成單一報告。

## **可用的資料集**

表中的資訊並非詳盡無遺。 請參閱「資料集中&#x200B;**欄位清單」一節**，以取得資料集中所有欄位的完整清單。

| **資料集** | **內容** | **關鍵欄位** |
|----------------------------------------------------------|--------------------------------------------------------------------------|---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|
| **使用者** | 現役與已刪除學習者的學習者資料 | 名稱、電子郵件、使用者 ID、管理員、活動欄位、狀態 |
| **成績單（學習物件）與成績單（模組）** | 報名與完成紀錄 | 註冊日期、完成日期、進度百分比、狀態 |
| **學習物件** | 課程、學習路徑與認證資料 | 學習物件名稱、學習物件 ID、類型、型錄、目錄標籤、狀態 |
| **學習物件實例** | 多實例課程的實例層級詳細資訊 | 實例名稱、實例 ID、註冊限制、截止日期 |
| **目錄** | 目錄中繼資料與目錄標籤鍵值對 | 作者姓名、創建日期、持續時間、格式。 **目錄標籤欄位由客戶自行設定**。 只有當你的帳戶設定了目錄標籤時，它們才會出現。 您看到的標籤名稱與值將反映您自己的設定。 |
| **使用者群組** | 使用者群組成員資格與階層結構 | 建立日期、成員數、名稱、狀態 |
| **模組** | 教室、虛擬教室及電子學習模組的課程詳情 | 模組編號、講師姓名、開始時間、結束時間、地點 |


>[!NOTE]
>
>對於透過目錄共享從其他帳戶取得的課程， **學習物件資料集中的「作者名稱** 」欄位會回傳來源帳戶的原始作者名稱。 這與標準的 ALM 管理介面及固定報告不同，後者所取得課程會顯示「外部作者」。 此行為僅適用於 Report Builder，且僅適用於對等（接收）帳戶。

## 資料集如何結合

並非所有資料集組合都能合併在一份報告中。 資料集必須在 Adobe Learning Manager 的資料模型中共享邏輯關係，才能進行合併。 當您新增第一個欄位時，報表建構器會篩選剩餘的資料集，只顯示相容的資料集。 如果資料集顯示為灰色，表示無法直接與您已選取的欄位連接。

這表示該資料集無法與您已選取的欄位合併。 這是資料模型中的一個硬性限制。 這兩個資料集不共用相容的連接路徑。

一個常見的例子是 **「合規率** 」導出欄位。 當選擇合規百分比時，**會停用逐字稿**、**模組轉錄****及 LO 實例**&#x200B;資料集。合規百分比是在使用者或使用者群組層級，針對學習物件與目錄計算的。 它僅設計用於與 **使用者**、 **使用者群組**、 **學習物件**&#x200B;及 **目錄** 欄位及篩選器一起使用。

若要使用已停用的資料集，請取消選取造成衝突的欄位，然後新增所需的資料集。

>[!NOTE]
>
>如果產生的報告包含課程資料但不含學習路徑資料，請檢查您是否已將學習物件資料集與模組資料集合併。 模組直接連結到課程，但不會直接連結到學習路徑。 因此，當包含模組欄位時，Report Builder 可能只會回傳課程紀錄，並過濾學習路徑。 若要報告學習路徑，除非報告專門用於分析課程層級的模組資料，否則請避免新增模組欄位。

下列連接關係是從報表建立器資料模型中擷取的。 了解它們有助於你在建立報表前規劃要合併哪些資料集。

### Hub 資料集

兩個資料集充當中央樞紐。 大多數其他資料集透過它們相互連結：

* **註冊** 資料集（註冊資料集），主要事實表。 它可直接連結至 **User（註冊的學習者）、** Learning Object（他們報名的學習對象&#x200B;**），並透過學習物件連結模組****、**&#x200B;目錄&#x200B;****、目錄標籤&#x200B;**和** LO 實例&#x200B;**。**
* **模組成績單** （moduleTranscript 資料集）— 模組層級的進度事實表。 它連接至 **User** 和 **Module，而 Module** 再連結到 **Learning Object**。

大多數結合學習者、課程與完成度資料的報告，都是透過這兩個中心之一建立的。

### 別名關係

資料模型中的某些欄位會透過命名角色而非直接學習者 ID 加入 **使用者** 實體。 這些是別名外鍵。 它們指向相同的使用者資料表，但代表不同的角色：

* **講師**：模組加入使用者，成為本次課程的講師
* **作者**：學習物件作者會以學習物件的作者身分加入使用者
* **管理員**：使用者自我連接，以代表學習者的管理者
* **完成者**：註冊與模組成績單各附有獨立的「完成者」使用者參考資料

這也是為什麼一份報告可以同時顯示學習者的名字和其講師姓名。 它們都是透過不同的連接路徑從使用者實體傳來的。

### 使用者群組資料集類型

**使用者群組**&#x200B;類別包含數個不同的資料集檢視，每個檢視涵蓋不同類型的群組：

| **資料集** | **群組類型** |
|---------------------------------------------------------|---------------------------------------------------------------|
| **使用者群組** （userGroup） | 所有使用者群組。 將此作為主要使用者群組資料集 |
| **使用者群組（活動欄位）（** active_field_user_group） | 根據活動欄位值（例如區域、部門）分類的群組 |
| **使用者群組（團隊）（** team_user_group） | 基於管理者階層的群組 |
| **使用者群組（自訂）（** custom_user_group） | 手動設定的自訂群組 |
| **使用者群組（內建）（** inbuilt_user_group） | 系統定義群組 |

基於檢視的使用者群組資料集（**Active Field**、Team **、****Custom**、**Inscript**）在結構中沒有直接的外鍵關聯，它們是 SQL 檢視。這表示它們的連接限制比核心 **使用者群組** 資料集寬鬆。 在將使用者群組資料與註冊或逐字稿資料合併時，請使用核心 **使用者群組** 資料集，以獲得最可靠的結果。

## 衍生欄位

衍生欄位是由 Report Builder 預先計算的欄位。 它們會在欄位選擇器中與標準欄位分開列出。

| **導出欄位** | **它計算的內容** | **所需資料集** |
|-------------------------|-------------------------------------------------------------------------|-----------------------------------------|
| **合規率** | 完成符合法規標籤課程的必修學習者百分比 | 使用者群組、學習物件、成績單 |
| **完成率** | 完成次數除以註冊人數 x 100 | 成績單或學習物件 |
| **註冊使用者數** | 學習物件的註冊學習者總數 | 學習物件 |
| **完成次數** | 學習物件的總完成次數 | 學習物件 |
| **起始計數** | 已開始但尚未完成的學習者 | 學習物件 |
| **會員人數** | 使用者群組中的使用者數量 | 使用者群組 |
