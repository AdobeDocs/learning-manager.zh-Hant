本次 Adobe Learning Manager 版本引入多項新功能與強化，旨在簡化平台並擴充其功能。 這些更新簡化了日常工作流程，改善學習內容的組織與傳遞方式，並使整體體驗更加一致且直覺。

## 報表建構器圖表與儀表板

Adobe Learning Manager 現已支援在 Report Builder 中使用圖表與儀表板，讓管理員能直接在平台上視覺化報告資料。 管理員可從報告欄位建立圖表，且每個圖表中提供彙總與篩選功能。

報告建構器支援以下圖表類型：

* 數量很大
* 折線圖
* 條形圖
* 圓餅圖
* 樞紐分析表

報告儀表板會儲存由單一報告建立的圖表。 自訂儀表板結合多個報表的圖表，例如註冊資料與使用者資料，並支援最多 20 個小工具。 屬於報告的圖表會在您分享報告時共享。 這有助於管理員將目前的報告資料集中在一個檢視中，而不必重複執行報告。 圖表最多可顯示 10,000 個資料點，樞紐分析表則顯示最多 100 列與 100 欄。 如果圖表超過限制，請套用篩選器縮小結果範圍。 儀表板目前無法匯出。

## Insights 代理報表在報表建立器中

管理員現在可以繼續在 Report Builder 中處理 Insights Agent 的答案。 當 Insights Agent 回答問題時，Report Builder 會以平行步驟將同一查詢對應到自身欄位。 管理員可以開啟、檢視、編輯並儲存報告。 在此，您可以使用與其他報表（例如訂閱）相同的報表建構器功能。

如果問題的一部分無法用 Report Builder 欄位表達，報告會將該部分列為空白。 如果缺失的部分是問題的核心，報告就不會提供。 複雜的查詢可能會產生較少的結果，因此在依賴報告之前，請先檢視每份報告。

## Adobe Experience Manager 資產整合

Adobe Learning Manager 現已與 Adobe Experience Manager 資產整合，讓作者能直接從集中式儲存庫存取並使用核准的學習內容與影像資產。 這省去了數位資產管理器（DAM）中資產管理團隊與 Adobe Learning Manager 課程建置團隊之間的手動下載與上傳步驟。

它改變了什麼：

* **存取核准資產：** 作者可在不離開 Adobe Learning Manager 的情況下瀏覽並選取 Experience Manager 資產，因此課程使用目前已核准的檔案，而非可能過時的本地複本。
* **保持課程資產最新：** 當資產在 DAM 中變更時，更新可自動流入使用該資產的課程，並在資產修訂時保持內容一致。
* **存取權依照既有權限進行：** 作者只會看到他們在 Experience Manager 資產中已擁有存取權的資產，因此在 Adobe Learning Manager 中瀏覽時會尊重與 DAM 本身相同的權限。

結果是從資產到學習者之間，有單一且受規範的路徑，減少了手動作業，也減少了版本不符的情況。

## 檔案提交功能增強功能

檔案提交模組現支援團隊提交及基於評分標準的評估。 新增設定還會控制提交是否需要講師核准。

### 隊伍提交

講師現在可以為檔案提交建立團隊。 每隊為整個團隊提交一份檔案。 講師會評估提交的作品一次，結果適用於每位會員。 團隊形成有兩種方式：講師手動建立團隊，或是依據每隊成員或團隊數量，在實例開始日期前依排定流程建立團隊。

講師可在新的 **Teams 管理** 頁面管理團隊，並在團隊提交頁面上檢視工作。 當需要變更時，例如團隊成員離職，講師也可以取消已核准的提交，以解鎖團隊。 一個團隊最多可容納 100 名成員。 學習者可以查看自己的團隊、成員以及評估結果。 課程發佈後，團隊模組無法新增或刪除。

### 以評分標準為基礎的評量

作者現在可以為檔案提交模組定義一個稱為評估計畫的評分標準。 評分標準支持有評分選項的客觀題目，以及以書面複習為主觀題目。

作者也可以設定以下設定：

* 學習者是否在提交前查看以評分標準為基礎的評量題目
* 無論評分是整體總分，還是每個標準的分數

每個問題都可以標記為必答，並設定以允許審查者發表評論。 以評分標準為基礎的評量最多可包含 100 題，作者需針對每個地區分別輸入問題。 課程發佈後，只有題目文本可以變更。

### 講師核准或自動完成

作者現在可以選擇檔案提交是否需要講師核准或自動完成。 此設定與評估計畫無關。

## 學習助理的情境協定模型伺服器

ALM 讓學習者能透過模型情境協定（MCP）伺服器，存取他們既有的工具中的學習內容。 學習者可從任何地方存取 Learning Manager，包括 ChatGPT、Claude 及自訂代理程式。 在整合管理應用程式中設定伺服器，讓管理員能存取六項學習者核心工具。 其中包括兩個學習助理工具：Answer Agent 與 Personalized Learning Path。

伺服器提供以下功能：

* 搜尋
* 名單登記
* 取得學習物件
* 取得使用者設定檔
* 回答學習內容問題
* 取得個人化學習路徑

管理員可以編輯每個工具描述，以新增組織特定的範例。 用戶端會從伺服器的元資料讀取授權細節，因此安裝只需要用戶端 ID 和用戶端密鑰。

## 個人化學習路徑編輯與品牌標籤條

學習者現在除了現有透過聊天細化主題與課程清單的選項外，還能在單一步驟中移除建議主題或課程。

管理員現在可以透過品牌頁面重新定位學習者首頁上的個人化學習路徑條。

## 在虛擬教練中透過角色扮演練習技巧

Adobe Learning Manager 現提供 Virtual Coach，一套由 AI 驅動的角色扮演與教練解決方案，讓學習者在面對工作前能練習逼真的職場對話。 範例包括銷售異議、客戶升級處理及績效評估。

作者利用範本或 AI 助理，從自己的參考資料創建情境，學習者則與即時調整回應的 AI 角色對話。 每次課程結束後，學習者都能即時獲得關於知識與溝通風格的評分與教練回饋，並依據作者所定義的標準進行衡量。

Virtual Coach 支援九種語言，可作為獨立工作輔助工具使用，或嵌入課程中。

## 學習者助理中的學習路徑引用

學習助理的回答現在會引用包含原始課程的學習路徑，以及課程本身。 學習者可從引用中開啟課程概覽或學習路徑頁面。 從工作輔助工具中擷取的答案包含下載連結。 這有助於學習者找到能解答他們問題的訓練內容。

## AI 助理配置

管理員助理提供兩個代理程式：Insights 代理程式與知識代理程式。 它們可以單獨設定。 學習助理提供三種代理：知識代理、回應代理與學習路徑代理。 它們可以與目錄設定一併設定。

## Webhook 用於講師對學習物件實例的編輯

學習物件實例修改 webhook 現在會在講師編輯虛擬教室課程時觸發，除了管理員與作者變更外。 如課程時間、場地及報名人數限制等變動會觸發此現象。 無頭客戶可透過公開 API 取得課程詳細資訊，並將更新傳遞給學習者。

## 合規小工具中的多重報名課程

合規小工具現在會列出學習者必須完成的每一個多重報名課程的實例。 每個項目都會顯示實例名稱。 如果某個實例有截止日期，任何沒有截止日期的實例都會被隱藏。 公開 API 的註冊端點透過一個可選參數支援相同的行為。

## 重新寄送虛擬教室課程邀請

擁有課程編輯權限的管理員現在可以從實例頁面重新發送會話邀請。 選擇 **「重新寄出**」，搜尋「學習者」，然後傳送。 此選項適用於目前及未來的虛擬教室課程。 對於多個實例中的學習者，邀請只會發送到所選實例。 未註冊課程的學習者會被跳過並附警告。

## Adobe Connect 錄影檢視自動出勤

Adobe Learning Manager 現在會在學習者播放錯過的虛擬教室課程錄影時，自動標記出席紀錄。 排程整合會從 Adobe Connect 擷取檢視器資料，並將播放時間與帳戶設定的完成條件進行比較。 管理員可在整合管理應用程式中設定排程。 Adobe Learning Manager 在判定出席時僅考慮實際觀看時間，因此跳過錄影不計入完成標準。

## 適用於課程與實例的電子郵件建構器

Adobe Learning Manager 中的電子郵件建構器允許管理員與作者建立品牌化的學習者溝通範本。 在 2026 年 12 月版本的 Learning Manager 中，完整的電子郵件建構器體驗已適用於課程層級及實例層級的電子郵件。 作者可以在繼承管理員定義的版面配置與格式的同時，自訂這些電子郵件。

使用 Email Builder，您可以：

* 建立可重複使用的電子郵件版面配置
* 套用組織品牌
* 自訂橫幅與簽名
* 定義預設字型與顏色
* 標準化課程與學習計畫間的溝通

管理員負責建立全帳戶的電子郵件範本與版面配置。 作者可在課程層級及實例層級自訂電子郵件，無需從零重建範本。

橫幅與簽名設定已移動。 先前這些設定會出現在獨立 **的設定** 標籤中。 該標籤已被移除， **橫幅** 與 **簽名** 現在會顯示在 **全域版面配置**&#x200B;中。

### 電子郵件建構器階層結構

Email Builder 採用階層結構。 每個層級都繼承自其父層級，並允許本地自訂。

| **等級** | **它提供什麼** | **誰負責客製化** |
|-------------------|---------------------------------------------------------------------------------------------------------------------|-----------------------|
| 帳戶配置 | 品牌、字型、顏色，以及頁首與頁尾結構 | 管理者 |
| 帳戶範本 | 全球電子郵件樣式、共通訊息元件與共享品牌 | 管理者 |
| 課程範本 | 課程專屬電子郵件，例如報名訊息、課程提醒、結業電子郵件及課程通知 | 作者 |
| 實例範本 | 最高層級的自訂，例如群組專屬、會話專屬或區域訊息 | 作者 |

所有課程皆可繼承自帳戶範本。 課程電子郵件會繼承組織的版面配置，並允許內容自訂。

### 版面繼承

範本會連結到最近的可用版面配置。 若存在實例層級版面配置，則會連結至實例層級範本。 如果不存在，範本會連結到最近的父版面配置。 你可以查看版面配置來自哪一層。

當範本連結到版面配置時：

* 品牌塑造會自動流入範本中。
* 作者只更新內容。
* 此版面配置可減少訊息間的重複。

您可以將範本與其版面配置解除連結。 解除連結範本後：

* 範本保留其現有的設計。
* 未來的版面更新不會影響範本。
* 範本會變得可獨立編輯。

版面繼承取決於可用的父版面。 當兩者層級同時存在時，實例層級的電子郵件會覆蓋課程層級的範本。

### 管理員與作者工作流程

管理員使用帳戶層級範本來維持帳戶內訊息的一致性，他們透過建立版面配置與範本來管理，然後發布品牌標誌。

當同儕需要不同的訊息時，作者會使用實例層級的範本，並透過課程實例來管理這些訊息。

### 課程及實例電子郵件的電子郵件建構器可用性

如果您的帳戶已啟用電子郵件建構器，您將自動收到新的變更，無需採取任何行動。 現有的電子郵件功能仍可獨立於 Email Builder 的遷移活動運作。

## 學習工具互通性中的自訂學習者屬性

Adobe Learning Manager 現在可以透過 Learning Tools Interoperability 的選用名稱與角色配置服務端點讀取自訂學習者屬性。 它也會讀取發射請求中的訊息。 像國家或城市這類屬性會儲存在可分組的個人檔案欄位中。 啟動參數需要前綴，以便 Adobe Learning Manager 能辨識它們。 有些學習系統，例如 Moodle，並不支援這個端點。

## 討論區講師通知

無頭客戶現在可以寄送討論區活動摘要給講師與班級經理。 透過 API，你將訂閱者加入看板。 他們會以您設定的間隔，在一封電子郵件中收到新貼文、留言和回覆。 喜歡與不喜歡的資訊不包含在內。 你透過 API 開啟這個功能。

## 管理員目錄搜尋中的相關性排名

在管理檢視中的目錄搜尋現在會依相關性排序結果，使用與 Learner 相同的搜尋服務，其他地方則可在管理員搜尋中使用。 先出現完全匹配的版本，例如帶有特定日期的目錄名稱，接著是部分匹配。 輸入時的建議清單順序相同。

## 從 Adobe Workfront 同步工作階段取消

在 Adobe Workfront 中取消的課程會透過遷移流程帶到 Adobe Learning Manager，無需手動步驟。 移轉會新增一個可選的狀態&#x200B;**欄位，可接受**「啟用&#x200B;**」或**「已取消&#x200B;**」。**&#x200B;空白值會保持工作階段不變。 透過遷移所做的取消，其行為與在 Learning Manager 介面中所做的取消相似。 學習者、講師、管理員、作者及管理者都會收到相同的取消郵件。

對於已取消的工作階段，有兩種行為：

* 移轉不會對已取消的工作階段套用詳細變更，且會針對這些資料列傳回驗證錯誤。
* 將狀態設為「啟用」會重新啟動會話，接著您可以更新其詳細資訊或再次取消。

會話更新仍維持原有運作。

## 名字字元限制

Adobe Learning Manager 現在接受最多 255 個字元的名字，原為 63 個字元。 這適用於介面新增的使用者、透過 CSV 匯入以及自我註冊時新增的使用者，因此來自其他系統的使用者同步不再因名稱過長而失敗。

當您從外部系統遷移使用者或自動化建立使用者時，這特別有幫助。

自 2026 年 12 月版本起，名字欄位最多可容納 255 個字元。 早期版本最多接受 63 個字元。

>[!NOTE]
>
>此限制適用於您帳戶中的所有使用者，不論其角色為何。 現有使用者及其姓名不會受到此變更的影響。

您可以在新增或編輯使用者時以以下方式輸入長名稱：

* 在管理介面中新增單一使用者
* 編輯現有使用者
* 使用 CSV 檔案匯入使用者
* 透過自我註冊方式註冊使用者
* 新增外部使用者

長名稱可能比介面某些部分的可用空間還要寬。 為了保持版面易讀，Adobe Learning Manager 會在以下緊湊區域縮短長名稱：

* 表格儲存格
* 下拉清單項目
* 搜尋結果

若要查看完整名稱，請將滑鼠移至縮短後的名稱上。

## 課程與學習路徑的徽章資訊

當作者新增課程或學習路徑時，會顯示一個視窗，列出現有課程及學習路徑及徽章資訊。 視窗會顯示名稱、類型（課程或學習路徑）、出版狀態及課程格式，例如自學進度、虛擬、教室或混合式。

## 非登入功能增強功能

Learning Manager 現在能在不需要使用者登入的情況下，受控地存取學習內容。 管理員可以指定哪些目錄是公開的，而作者則可以決定哪些課程和模組在沒有帳號的情況下可用。 公開內容以可爬蟲、AI 可讀的頁面形式發布，使學院可透過搜尋引擎及 Claude 和 ChatGPT 等 AI 助理被發現。 匿名使用會以每位訪客為單位追蹤，並與登入使用分開報告。

### 無需登入即可消費內容

造訪您的公共學院的訪客現在可以直接從課程概覽頁面播放所選內容，無需帳號、電子郵件或表單。

* **開啟或關閉未登入存取：** 管理員可為整個帳戶開啟或關閉未登入內容的使用。
* **無需登入即可取得課程或模組：** 作者可讓整門課程無需登入即可使用，或僅開啟特定模組，例如在進入門檻的進階內容之前先開啟免費入門模組。
* **從課程繼承設定：** 學習路徑與認證依照課程內的設定運作，無需額外設定。
* **無需登入即可檢視內容：** 未驗證的學習者可在不登入帳戶的情況下查看可用的未登入內容。
* **僅限自我進度內容：** 未經登入，第三方授權內容及取得的目錄內容無法提供。
* **匿名消費報告：** 可產生每月未登入消費報告。
* **支援跨平台非登入學習：** 原生 Adobe Learning Manager 網頁與行動版、無頭部署，以及基於 Adobe Experience Manager 小工具的學院支援非登入內容的使用。

### 選擇哪些目錄為公開

管理員現在可以選擇在公共學院中出現的特定目錄。 只有這些目錄才能被匿名訪客瀏覽，並被搜尋引擎和 AI 助理索引，因此測試課程或內部內容保持隱私。
 
### 在搜尋引擎與 AI 助理中被找到（測試版）

Adobe Learning Manager 現在能讓你的公開學院被 Google 等搜尋引擎以及 ChatGPT 、Claude 和 Gemini 等 AI 助理發現。 你的課程隨後會出現在搜尋結果和 AI 生成的答案中，這些答案會歸屬於你的學院。

* 帳戶層級的控制允許管理員決定爬蟲是否能存取公開學院，以及其內容是否可以被索引。
* 每個學院都會有自己的網站地圖和robots.txt，這些都是根據你公開的目錄自動生成的。
* 頁面是預先渲染好的，讓不執行 JavaScript 的 AI 助理也能讀取這些頁面。
* 爬行者只會看到訪客能接觸到的東西。 封閉內容絕不會被揭露。
* Meta 標題、描述與結構化資料：Adobe Learning Manager 會根據學習資料，自動為每門課程、學習路徑與認證產生這些資料。

>[!NOTE]
>
>在原生 Adobe Learning Manager 上進行 AI 與搜尋發現，需要自訂網域。 無頭部署需要在自身環境中實作部分設定。

已停用的課程或巢狀學習路徑會從較高階的學習物件中移除，該物件仍會持續開放以接受新報名。 退休課程不再使學習路徑無法使用。

## 自我註冊個人檔案的未登入頁面 URL

自我註冊檔案讓外部使用者，例如合作夥伴或多個組織成員，建立自己的 Adobe Learning Manager 帳號。 每個個人檔案現在都可以擁有自己的可分享、未登入的選單 URL，內建於 Experience Builder 中。

當使用者從透過該 URL 到達的頁面選擇 **「註冊」** 時，他們會被加入該 URL 所屬的個人檔案中。 這會讓來自不同組織的使用者，例如不同機構或合作夥伴公司，分別存在不同的個人檔案。

## 儲存 Learning Path 註冊的最後存取日期

Adobe Learning Manager 現在允許您將自訂的中繼資料（例如最後存取日期）附加到學習路徑的報名中。 你透過 API 設定並讀取它，這有助於你追蹤對所指派學習路徑的時限存取情況。

課程報名已透過 API 支援最後存取日期，該 API 控制學習者存取課程的時間長短。 Learning Path 報名現在提供通用的中繼資料欄位，讓您能儲存最後存取日期或其他想追蹤的值。

## 使用 Job API 匯出報表建構器報表

此版本的 Adobe Learning Manager 新增了新的 Job API 工作類型。 `generateCustomReport`傳遞報告 ID，即可自動匯出您在 Report Builder 中建立的任何報告。

結合報告建構器中的新 L2 測驗資料集，您現在可以：

* 將跨多門課程與模組的題目層級（L2）測驗資料匯出於單一報告，而非每門課程只執行 `generateQuizReport` 一次。
* 自動化定期匯出，例如每日增量匯出至您的資料倉儲或商業智慧工具。

現有的工作類型（包括 `generateQuizReport`）保持不變。

## 下載報告中的欄位標題變更

報表建構器現在會在下載報表的預設欄位標題中包含資料集名稱，因此學習物件資料集中的名稱會顯示為 **學習物件 - 名稱** ，而非 **名稱**。 對於彙總欄位，標題也會包含功能，例如 **學習物件數量 - ID**。 如果您在欄位 **的別名** 欄位中輸入自訂名稱，該別名將被用作標題，且保持不變。

升級後，未使用自訂別名的現有報告會顯示更新後的標題，而報告資料、篩選條件及排程則不受影響。 如果您的腳本、試算表、商業智慧儀表板或整合以標題引用欄位，請更新為新名稱，或設定自訂別名以保留特定標題。

**它有幫助的地方：**

* **高風險評估：** 在重要評估期間，減少存取未授權應用程式或資源的機會。
* **彈性評估管理：** 允許作者僅在需要額外限制的小測驗時，要求使用安全考試瀏覽器。

## Adobe Learning Manager 2026 年 12 月版本的 API 變更

### 書籤 API 排序與已退休的內容處理

學習者可以將訓練加入書籤，方便日後重溫。 過去，書籤 API 會以無特定順序回傳已儲存的訓練，防止無頭整合先顯示最近儲存的訓練。 已停用學習物件的書籤也仍留在清單中，導致出現「找不到頁面」的錯誤訊息。

這次更新同時修正了以下兩項問題：

* 書籤現在會先回傳最新的。
* 已退役學習物件的書籤將不再回傳。

不會新增端點、參數或回應屬性，因此現有整合會持續運作，無需變更。

### 討論區講師通知的 API

本次版本新增支援討論區講師通知的新 API。 利用這些資源訂閱講師和班級經理的討論區，並控制哪些活動出現在他們的摘要郵件中。

### 在 Learner 應用程式中支援多註冊實例的 API

註冊 API 現在支援 Learner 應用程式中的多重註冊實例。 新增可選 `includeMultiInstanceEnrollments=true` 參數以 `GET /enrollments` 包含它們。 預設為 `false`，因此現有的整合，包括無頭實作，都能維持不變的運作方式。

### Learning Paths 註冊的最後存取日期

您現在可以在學習路徑註冊中儲存自訂的元資料，例如最後存取日期，並透過 API 設定與讀取。 這有助於您追蹤對所指派學習路徑的限時存取情況。

* 在現有報名或註冊學員時，使用管理權杖設定中繼資料。
* 用管理員或學習者憑證閱讀。

這些元資料是用來追蹤你的。 它不控制存取，也不會套用在路徑上的課程上。

### 報告建構器匯出作業 API 工作類型

Job API 新增了工作類型，當您 `generateCustomReport`傳遞報告 ID 時，會匯出任何已儲存的 Report Builder 報告。 透過全新的 L2 測驗資料集，你可以將跨多個課程的題級測驗資料匯出成一份報告，並自動化重複匯出。

現有的工作類型（包括 `generateQuizReport`）保持不變。

### Zoom 連接器的 API

使用這些 API 在 Adobe Learning Manager 中檢視和管理 Zoom 連接器。 使用它們來擷取現有的 Zoom 連線、儲存 Zoom 認證、建立或更新連線，以及管理使用者群組與自訂角色的存取權限。

**API 序列**

請依照下列順序使用這些 API：

| **步驟** | **API** | **目的** | **認證** |
|------------------------------------|---------------------------------------------------------------|---------------------------------------------------------------------------------------------|-----------------------------------------------------|
| 1 | `POST /ctr/authcred/uuid/20012    ` | 儲存 Zoom 憑證。 | 整合管理工作階段 |
| 2 | `POST /ctr/app/esconnect  ` | 建立 Zoom 連線或更新現有連線。 | 整合管理工作階段 |
| 3 | `PUT /ctr/xtsa/{connectionId}/access` | 設定可以使用此連線的使用者群組與自訂角色。 | 整合管理工作階段 |

**驗證與權限**

這些 API 採用基於工作階段的驗證，並要求使用者以 Adobe Learning Manager 中的整合管理員身份登入。
