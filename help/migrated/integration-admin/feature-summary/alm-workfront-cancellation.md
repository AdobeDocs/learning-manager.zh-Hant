# ALM-Workfront 取消/更新觸發器

## 概觀

Adobe Learning Manager（Learning Manager）現在可以根據 Workfront 所做的變更，取消並重新啟用講師主導與虛擬講師主導（ILT/VILT）課程。 如果您的組織在 Workfront 中排定課程，並透過 Workfront 至 Learning Manager 的遷移將其導入 Learning Manager，您可以在遷移資料中將每個課程的狀態設定為「啟用中」或「已取消」。 Learning Manager 會以管理員在使用者介面中取消課程的方式套用變更。

透過遷移取消會話的行為與在 Learning Manager 使用者介面中取消會話相同。 唯一特別強調的差異是重新啟用，詳見 [「重新啟動已取消的工作階段](#reactivate-a-cancelled-session)」。

### 需求

課程更新，例如日期與時間、講師、地點或連結，以及容量，已透過遷移從 Workfront 流向 Learning Manager。 取消則沒有。 當 Workfront 中某次工作階段被取消時，Learning Manager 無法得知，導致以下問題：

* 學員繼續註冊已停止的課程，導致混亂與缺席。
* 管理員必須在 Learning Manager 中手動重複取消。
* Workfront 與 Learning Manager 出現了不同步，這削弱了 Workfront 作為排程真實來源的地位。

### 運作方式

1. 交付經理在 Workfront 中取消了一場工作階段。
1. 遷移資料中的會話列包含新的會話狀態欄位，該欄位設為「已取消」。
1. 系統管理員透過 API 執行遷移。
1. Learning Manager 會將配對課程標記為已取消，並發送與使用者介面取消相同的通知。

>[!NOTE]
>
>此功能延伸現有的遷移流程，而非新增第二條即時整合路徑。

## 使用案例

以下角色會參與在 Workfront 中開始的取消。

### 涉及的角色

| 角色 | 說明 |
|---|---|
| 交付經理 | 在 Workfront 中排程並管理訓練行事曆，包括取消課程。 交付管理員不使用 Learning Manager 的使用者介面。 遷移是他們取消通知送達 Learning Manager 的唯一途徑。 |
| 系統管理員 | 透過 API 執行遷移。 此角色負責操作 Workfront-to-Learning Manager 流程，並與交付經理及 Learning Manager 管理員分開。 |
| 行政 | 在 Learning Manager 使用者介面中管理課程與課程資料。 管理員不再需要在接獲 Workfront 變更通知後手動取消工作階段。 |
| 作者 | 擁有 Learning Manager 使用者介面中的課程與課程內容。 |
| 講師 | 被分配到各個工作階段。 講師能看到正確的課程狀態，並在所指導的課程被取消時收到通知。 |
| 學習者 | 已透過 Learning Manager 註冊課程。 學習者會在課程被取消時立即通知。 |

### 常見情境

| 劇情 | 你在做什麼 | 結果 |
|---|---|---|
| 例如，Workfront 中會話被取消，例如因為某個資源無法使用或供應商出現問題。 | 將該工作階段的遷移列狀態設為「已取消」，然後執行遷移。 | 課程會在 Learning Manager 中取消，受影響的人會收到通知。 |
| Workfront 中進行中工作階段變更的詳細資料。 | 將變更的值包含在遷移列中。 將工作階段狀態設為「啟用」，或保持空白。 | 會話已更新。 Learning Manager 會發送一封會話更新的電子郵件。 |
| 已取消的工作階段會在 Workfront 中恢復。 | 將遷移列中的工作階段狀態設為「啟用」並執行遷移。 | 該工作階段會自動生效，並可再次修改與取消。 |
| 對於已取消的工作階段，會傳送更新的詳細資料，但不會將狀態設為「啟用」。 | 使用者不需要採取任何行動。 | 工作階段會持續取消，該列會回傳驗證錯誤，且未變更任何詳細資訊。 |
| 遷移列不包含會話狀態。 | 將該欄位留空或省略。 | Learning Manager 中會話的目前狀態保持不變。 |

## 主要特色

* **會話狀態欄位。** 遷移結構包含一個可選的工作階段狀態欄位，支援「啟用」與「已取消」。
* **透過遷移取消。** 當某列狀態為「取消」時，Learning Manager 中的匹配工作階段會被取消。 Learning Manager 使用與遷移已使用相同的匹配金鑰來建立與更新工作階段。
* **Learning Manager 中無需手動操作。** 管理員無需在使用者介面中再次取消該工作階段。
* **這跟使用者介面裡的取消行為一樣。** 報名處理、面向學習者的可見性、報告、稽核追蹤及通知，皆可從使用者介面中匹配取消。
* **重新啟動。** 您可以透過在遷移資料中明確設定已取消的工作階段狀態，將該工作階段重新設定為「啟用」。
* **為已取消的會話提供保護。** 除非該列明確將狀態設為「啟用」，否則遷移不會變更已取消的工作階段詳細資訊。
* **向下相容性。** 狀態欄位為選填，因此現有的遷移檔案在不作變更的情況下仍能正常運作。
* **完整通知。** 學習者、講師、管理員、作者與管理者會收到與使用者介面取消郵件相同的取消郵件。

## 會議狀態

Learning Manager 中的每個工作階段都處於兩種狀態之一。

| 州 | 意義 |
|---|---|
| 現役 | 預設狀態。 課程為現場進行，學習者可報名並參加。 |
| 已取消 | 課程取消。 已註冊的學習者、管理員、作者及管理者都會收到通知，因為他們在使用者介面中會收到取消通知。 |

### 遷移的州過渡規則

下表顯示在處理移轉列時會發生什麼事。 Learning Manager 會使用遷移中已用於建立與更新的匹配鍵碼來識別該工作階段。

| Learning Manager 目前的狀態 | 遷移列中的工作階段狀態 | 結果 |
|---|---|---|
| 工作階段不存在 | 啟用或空白 | 該工作階段會被建立為啟用狀態。 |
| 現役 | 啟用或空白 | 會話會持續進行。 列中變更的值會套用。 |
| 現役 | 已取消 | 會話會被取消，通知會被發送。 |
| 已取消 | 已取消 | 那一排被跳過了。 已取消的會話無法再次取消。 |
| 已取消 | 現役 | 會話會重新啟動。 列中變更的值會套用。 |
| 已取消 | 空白 | 課程仍維持取消狀態。 如果資料列的值有變更，則會回傳驗證錯誤，且不會更改任何詳細資訊。 |

### 會話狀態欄位的規則

* 每一列的欄位都是可選的。
* 當欄位為空時，工作階段將更新為「啟用」。
* 只有當欄位明確標示為「Active」時，工作階段才會透過遷移再次恢復為活動中。

在工作階段狀態欄中使用下列其中一個值：

* `state = Active`
* `state = Cancelled`

>[!NOTE]
>
>精確的欄位標頭與接受值正在確認中。 請使用您的遷移文件中指定的名稱。

## 已取消工作階段的更新

您無法透過遷移更新已取消的工作階段詳細資訊。 如果已取消的課程列包含變更的值且未將狀態設為「啟用」，Learning Manager 會回傳驗證錯誤，課程保持取消狀態，且既不會套用也不儲存變更後的詳細資料。 Learning Manager 不會針對此嘗試發送已更新的會話電子郵件。

### 使用遷移功能取消工作階段

當 Workfront 中某個工作階段被取消，且您希望 Learning Manager 反映變更時，請使用此程序。

**開始之前**

* 該課程已存在於 Learning Manager 中，並透過 Workfront 至 Learning Manager 遷移而匯入。
* 您知道遷移時用來識別該會話的匹配金鑰。

1. 在 Workfront **中**，取消該工作階段。
1. 在您用於遷移的工作階段 CSV 檔案中，找到該工作階段的列。 請確認匹配的金鑰與建立工作階段時所使用的金鑰相同。
1. 在工作階段狀態欄位輸入 **「已取消**」。
1. 透過 API 執行遷移程序。
1. 在 Learning Manager 中，確認該課程已取消。

Learning Manager 會將課程標記為取消，從使用者介面處理已報名的學習者，就像取消時一樣，並發送取消通知。 在 Learning Manager 使用者介面中不需要任何操作。

>[!NOTE]
>
>如果該工作階段已經取消，Learning Manager 會跳過該列。

### 更新目前的工作階段

對於活動中的工作階段，現有的移轉更新行為仍可使用。 將工作階段狀態設為「啟用」或保持空白，並將變更的值包含在列中。 您可以透過遷移流程持續更新日期與時間、講師、位置或連結，以及容量等詳細資訊。

啟用會保留現有的建立與更新行為。 「取消」會透過工作階段 CSV 遷移，呼叫使用者介面所提供的相同工作階段取消。

### 重新啟動已取消的工作階段

取消的工作階段只有在您明確將狀態設為「啟用」時才會回復為「主動狀態」。 您可以透過遷移或在使用者介面中編輯該工作階段來重新啟用工作階段。

1. 在工作階段 CSV 檔案中，找到已取消的工作階段列。 請確認匹配的金鑰與建立工作階段時所使用的金鑰相同。
1. 在工作階段狀態欄位輸入「啟用」。
1. （選用）更新列中您想變更的其他值，例如日期與時間、講師、地點或連結，或容量。
1. 透過 API 執行遷移程序。

會話會自動啟用，且其詳細資料可以被修改。 透過遷移或使用者介面重新啟用的工作階段，可以透過任一路徑再次取消。

>[!IMPORTANT]
>
>如果您傳送已取消的工作階段更新細節，但未將狀態設為「啟用」，該工作階段會保持取消狀態，且該列會回傳驗證錯誤。

## 通知

當會話因遷移而取消時，Learning Manager 會從使用者介面發送所有取消郵件。 收件人覆蓋範圍不會減少，且內容使用相同範本，因此收件人無法知道取消是如何開始的。

本次會議適用的受獎者如下。

| 受贈者 | 通知 |
|---|---|
| 學習者 | 已報名本次課程的學習者會被告知課程已被取消。 |
| 講師 | 分配到本次課程的講師會被通知取消。 |
| 經理人 | 經理會收到取消通知。 |

### 取消會話的電子郵件

取消的會話不會產生會話更新的電子郵件。 當課程取消時，日期與時間、講師、地點或連結，以及容量的變更不會觸發課程更新後的電子郵件。 僅對已取消的工作階段生效取消與重新啟用通知。

## 考量與限制

* 由於此功能使用遷移，Workfront 中取消的訂單會在遷移執行時傳送至 Learning Manager。 不支援基於 Webhook 的即時取消功能。
* 移轉無法變更已取消的工作階段詳細資訊。 要變更它們，請先將狀態設為「啟用」。
* 工作階段狀態欄位為選填。 省略該資料的列永遠不會改變會話的狀態。
* 此功能擴展了現有的遷移整合。 它並未新增第二條即時整合路徑。
* 遷移排程或觸發條件取決於您的組織用來執行該計畫的工具。 本指南並未定義固定的排程。
* 交付經理僅在 Workfront 中工作。 他們不需要存取 Learning Manager 使用者介面即可取消課程。

## 成功指標

| 測量 | 目標 |
|---|---|
| 管理員或客戶支援手動複寫的取消 | 在上市後一個完整發佈週期內，將 0 降為 0。 |
| Workfront 取消紀錄反映在 Learning Manager 中 | 100% 的取消事件在單一遷移週期內處理。 |
| 使用者介面與遷移取消之間的通知一致性 | 收件人覆蓋（管理員、作者、管理者及學習者）零缺口，取消課程時也無不必要的更新郵件。 |

## 疑難排解

| 子嗣 | 預期或可能的原因 | 動作 |
|---|---|---|
| 在 Workfront 中取消工作階段後，工作階段仍保持有效狀態。 | 遷移尚未處理取消，或遷移列未明確顯示已取消狀態。 | 驗證遷移輸入與處理結果。 |
| 取消會話的詳細資料不會改變。 | 在會話持續取消時，預期的行為。 | 將狀態設為「啟用」，然後重新啟用工作階段，然後套用變更。 |
| 取消會話不會寄出更新的會話電子郵件。 | 預期中的行為。 一般更新電子郵件會因取消工作階段而被抑制。 | 使用取消與重新啟用生命週期，而非僅提供詳細資訊更新。 |
| 會跳過一個取消列。 | Learning Manager 中的配對會話已經取消。 | 無需進一步取消。 如果必須回到啟用，請先重新啟動該工作階段。 |
| 收件人收到的取消郵件與使用者介面取消郵件相同。 | 預期中的行為。 遷移取消設計以符合使用者介面。 | 不需要採取行動。 |
| 當工作階段狀態為空白時，行為不明確。 | 在空白狀態處理上，來源需求存在衝突。 | 在依賴空白狀態進行任何轉換前，請先確認釋放行為。 |
