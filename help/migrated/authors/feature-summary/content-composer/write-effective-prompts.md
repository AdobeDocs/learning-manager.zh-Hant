# 在內容撰寫器中撰寫有效的提示

學習如何在內容撰寫器的每個階段撰寫有效的提示，從開場提示到簡報、大綱及課程編輯器，製作出準確且結構良好的 AI 生成課程，且需更少編輯。

內容撰寫者全程以對話式呈現。 每個階段產出的品質取決於你給它的品質。 本指南涵蓋如何在四個階段 **有效與 AI 溝通：首頁**、 **簡報**、 **大綱**&#x200B;與 **課程**。

## 第一階段：首頁-寫出你的開場提示

開場提示就是你的起點。 不需要完美。 內容撰寫者會閱讀你的提示，並用它來開啟對話。 即使是粗略的提示也能啟動流程;助理會在簡報階段提出後續問題，以補足缺失。

不過，更具體的提示意味著 AI 會更準確地預先填寫簡報，減少你生成大綱前的來回溝通。 如果你對受眾、主題和目標有明確的了解，就把它們寫進提示中。

一個模糊的提示會產生一個模糊的簡報。 模糊的簡報會產生一個通用的大綱。 一個通用的大綱會產生需要大幅編輯的課程。 提示階段的具體性會隨著後續的每個步驟逐步推進。

### Content Copmposer 期待什麼

內容撰寫者期望在一兩句話中完成以下內容：

- **學習者是誰** ？ 說明他們的職務和經驗程度。
  - **課程內容會涵蓋哪些** 內容？ 描述2到3個具體主題領域，而非廣泛的領域。 例如，「釣魚辨識、密碼衛生與多重身份驗證設定」比「IT 安全」更有用。
- **學習目標是什麼？** 描述你希望學習者完成課程後達成的結果或行為改變。

### 有效提示的解剖學

**[受眾 + 經驗層級]** + **[2-3 個特定主題]** + **[學習目標]**

**範例**：

我想為新進的銷售代表設計一門課程，涵蓋我們的企業定價層級及折扣審核流程。 最終，他們應該能自信地處理三大最常見的客戶異議。

分解說明：

- **受眾：** 新進銷售代表

- **主題：** 企業定價層級、折扣核准工作流程、三大常見反對意見
  - **學習目標**：自信地處理三大最常見的顧客異議——一個可衡量的行為結果，而非一個需要涵蓋的主題

選擇 **「開始」**&#x200B;後，內容撰寫者會 **開啟簡報** 階段。 檢視 AI 根據提示產生的預設欄位、標題、學習者資料和目標，並在產生大綱前修正任何不符合你意圖的內容。

### 有效提示的注意事項

| **包括** | **避免** |
|--------------------------------------------------------------------------------------------------------|--------------------------------------------------------------------------------------------------|
| 特定受眾角色（「新進銷售代表」、「第一線經理」） | 模糊的受眾（「全體員工」、「所有人」、「使用者」） |
| 2-3 個具體主題領域 | 一個提示中有6+主題——這些會產生過載的大綱;因此被拆分成獨立課程 |
| 一個範圍訊號——持續時間、深度或學習者結果 | 通用目標（「教他們所有關於X的知識」、「涵蓋所有面向」） |
| 影響語氣或深度的脈絡（「為了合規」、「針對非技術觀眾」、「情境導向」） | 向 AI 提問。 題目是簡短的，不是對話 |
| 學習者課程結束後能做什麼 | 課程內容（結構留給大綱階段） |

### 依課程類型的入門提示

| **課程類型** | **啟動提示** |
|--------------------------------|----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|
| **合規訓練** | 「我想為所有員工設計一門關於GDPR資料處理的課程，涵蓋什麼算是個人資料、如何正確儲存與分享資料，以及如果發生資料外洩該怎麼辦。」 |
| **新手介紹** | 「我想為新的 \[角色]創建一個入職模組，涵蓋 \[主題1\]、\[主題2\]和\[主題3\]。 |
| **技術能力** | 「我想為初級軟體工程師設計一門關於安全程式碼實務的課程，例如SQL注入防護、輸入驗證，以及如何閱讀SAST報告。」 |
| **軟實力** | 「我想為第一線零售經理設計一門建設性回饋課程，例如介紹SBI模式、如何準備回饋對話，以及如何後續跟進。」 |
| **政策與程序** | 「我想為倉庫員工設計一門手動操作程序課程，例如正確的搬運技巧、何時使用設備，以及如何報告近距離事故。」 |
| **產品訓練** | 「我想為客服人員設計一門退貨政策課程，例如涵蓋資格條件、如何在系統中處理退貨，以及如何處理升級處理。」 |
| **銷售賦能** | 「我想為中階客戶經理設計一門關於企業交易談判的課程，例如如何辨識決策者、如何利用我們的價值框架處理價格異議，以及何時該向銷售總監反映。」 |
| **領導力發展** | 「我想為首次擔任人事經理的人設計一門課程，教他們如何有效進行每週一對一會談，例如設定議程、給予表揚，以及及早解決表現不佳的問題。」 |
| **系統與工具訓練** | 「我想為剛接觸 Workday 的人資協調員設計一門課程，例如如何製作職缺申請、如何讓候選人進入招聘階段，以及產生人員報告。」 |
| **健康與安全** | 「我想為所有現場員工開設消防安全程序的複訓課程，例如涵蓋每個建築區域的疏散路線、如何使用滅火器，以及在非工作時間發現火災時該怎麼辦。」 |

## 第二階段：簡短-銳化AI的建議

提交提示後，Content Composer 會開啟簡報階段，預先填入三個欄位：課程名稱、學習者檔案與學習目標。 AI 會先問後續問題，讓你在產生輪廓前強化每個欄位。

這是一個對話階段。 你對 AI 問題的回答品質，直接決定它所產出大綱的品質。

### 課程名稱

AI 建議兩個標題選項。 選擇適合的，或自己打字。 如果兩者都不對，請描述這個差距：

「都不是。 這門課特別著重於審核流程，而非一般定價。」

一個好標題是面向學習者。 它描述的是學習者將能做到的事，而不是課程涵蓋的內容。

### 學習者概況

AI 會詢問角色、經驗程度，以及學習者目前遇到的困難。 具體說明他們知道什麼和不知道什麼：

| 沒那麼有用 | 更有用 |
|---|---|
| 「所有員工」 | 「熟悉敏捷但沒有企業安全合規經驗的中階軟體開發者」 |
| 「新手」 | 「早期職涯經理從個人貢獻者職位晉升，卻未接受正式管理訓練」 |
| 「我們的銷售團隊」 | 「新進客戶經理剛入職 90 天，熟悉 CRM 工具，但不熟悉企業定價結構」 |

### 學習目標

AI 會詢問學員完成課程後在工作中能做什麼。 這是最重要的簡報欄位——它控制 AI 在原始檔案中優先處理的內容、大綱的結構，以及測驗會考什麼。

將目標書寫為行為，以動作動詞開頭：

| 弱目標 | 強烈目標 |
|---|---|
| 「了解資料保護」 | 「識別個人資料，採用正確的儲存與分享程序，並依據組織的通報程序通報疑似外洩」 |
| 「了解異議處理」 | 「使用核准的訊息框架回應三個最常見的客戶異議，且不升級至銷售主管」 |
| 「了解入職流程」 | 「完成第一週的新職入職清單，提交必要的合規表格，並在不依賴 IT 協助的情況下使用所需工具」 |

>[!IMPORTANT]
>
>**在你產生大綱之前：** 大綱完全是根據簡報撰寫，而非你原本的提示。 在選擇 **「產生大綱**」前，請確認職稱是面向學習者，學習者檔案中列出特定角色與經驗層級，學習目標描述可衡量的工作行為。 明確的簡報會產生結構良好的大綱。 如果有哪個領域還是覺得很普通，現在就去精煉。  這樣可以省下後續大量編輯。

### 《簡報徵兆》還需要更多改進

- 學習者檔案中寫著「想了解 X 的員工」，而未列出具體職務和經驗層級
- 學習目標描述的是學科領域，而非可衡量的工作行為
- 標題是一個主題標籤（「IT 安全」），而非面向學習者的成果（「識別並回應釣魚攻擊」）

## 第三階段：大綱-透過對話編輯

確認簡報後，內容撰寫者會產生課程內容與主題結構。 你要先檢視並透過聊天面板申請修改，然後才產生完整課程。

目前版本的提綱編輯完全是對話式的。 你無法在畫布上選擇課程或主題來重新命名或重新排序。 所有變更皆透過輸入純語言請求完成。

這也是進行結構性變更最有效率的階段。 編輯大綱只需幾秒鐘。 重組生成課程所需的時間明顯長得多。

### 如何表達大綱編輯請求

要直接且具體。 請以目前的名稱命名課程或主題，描述你想要的改變，並可選擇說明原因。

**更名：**

- 「將第一課更名為『釣魚攻擊如何運作』。」
- 「將主題2.3改名為『升級路徑與時間軸』。」

**補充：**

- 「第二課新增一個關於QR碼釣魚的新主題。」
- 「第四課後再加一堂事件應變課程。」

**移除：**

- 「移除主題1.3。」
- 「刪除第五課。 這些內容會在另一門課程中涵蓋。」

**重新排序：**

- 「把第三課移到第二課。」
- 「將主題2.1移到第二課的結尾。」

**分裂：**

- 「第三課分成兩課，一課講垃圾郵件過濾器，一課講補丁管理。」

**合併：**

- 「將第四課和第五課合併成一堂課，叫做『事件回應與復原』。」

**再生：**

- 「重新生成大綱，並更強調密碼衛生和多重認證。」
- 「重新生成大綱——目前的結構對非技術讀者來說過於技術性。」

### 大綱階段無法做到的事

- 階層固定為課程>主題。 你無法建立子主題或三層結構。
- 此階段無法設定個別課程目標——簡報的整體學習目標適用於整門課程。
- 此階段無法新增元件或媒體。 這些都是在課程編輯器中新增的。

### 何時重生與何時編輯

| 當...... | 當...... |
|---|---|
| 整體結構是正確的，但個別名稱或主題需要調整 | 整體結構完全不符合你的意圖 |
| 你想要新增或移除特定項目 | 在產生第一個大綱後，簡報得到了大幅修訂 |
| 有一課需要拆分或合併 | 大綱感覺很通用，缺乏你組織的具體背景 |

## 第四階段：課程——透過助理精煉內容

當你核准大綱並產生課程後， **螢幕右側的「使用內容撰寫者** 創作」面板會保持開啟。 你可以用它來精煉、擴充或調整生成課程的任何部分，透過對話。

課程編輯器中的助理是為內容編輯任務設計的。 對於產品操作問題，請使用這些說明文件，而不是直接問助理。

### 如何表達課程編輯請求

**重寫或調整特定章節：**

- 「重寫第一課第二部分的段落，使其更簡潔——目標是三句話。」
- 「讓主題2.1的內容不那麼技術性。 觀眾沒有IT背景。」
- 「在第一課的介紹中加入一個真實世界的例子。」

**調整音色：**

- 「用更對話的語氣重寫第二課。」
- 「讓第3.2主題的內容更具權威性——這是一門合規課程。」

**擴充或新增內容：**

- 「在主題 1.3 加入一個情境範例，說明釣魚郵件可能的樣貌。」
- 「擴展多重身份驗證（MFA）部分，包含在行動裝置上設定的說明。」

**簡化或簡化：**

- 「將投影片5的文字縮短為三個重點。」
- 「用一句話總結第2.2主題的第二段。」

**調整測驗：**

- 「用更難的題目重新生成第二課的小考。」
- 「將第三題替換成一個情境題，關於如何辨識社會工程嘗試。」
- 「第一課測驗多加兩題，重點是MFA設定。」

**調整圖片：**

- 「將主題2.2中的圖片替換成展示社會工程情境的圖片。」
- 「為主題 1.1 生成一張圖片，說明筆電螢幕上的釣魚郵件。」

**新增或修改元件：**

- 「在主題3.1加上三個定價層級定義的翻頁卡片。」
- 「在第2.3主題中加入手風琴，並有升級步驟——每步一格。」
- 「將主題1.2的項目符號清單轉換成時間軸組件。」

### 課程助理無法做到的事

- 直接在畫布上重新命名課程或主題。 使用助理：「將第二課改名為『密碼衛生』。」
- 建立分支或自適應路徑。 課程結構是線性的。
- 新增課程或重新結構大綱。 結構性變動則需回到大綱階段。

## 各階段最佳實務

- **在開啟 Content Composer 之前，請描述你想建立的內容。** 事先草擬的句子通常比在輸入欄位壓力下打出來的句子更清晰。
- **投入時間在學習目標上。** 簡報中的目標控制大綱結構、來源檔案優先順序及測驗對齊。 一個具體且以行為為導向的目標，會在每個後續階段減少編輯。
- **在產生大綱前先細化簡報。** 大綱是根據簡報而建，而非原始提示。 一份明確且具特定學習者特徵與學習目標的簡報，能產生結構化且相關的大綱。
- **在生成課程前先編輯大綱。** 大綱階段的結構性變動只需幾秒鐘。 同樣的變更在生成賽道後會花更長時間。
- **使用課程助理來處理內容，而非結構。** 結構上的變動、新增課程內容、重新排序主題，都應該放在大綱階段。 使用課程助理來精煉文字、語氣、範例和測驗題目。
- **每個請求都要具體說明。** 說出你想改變的課程、主題、投影片或問題。 「讓它更好」讓 AI 沒有什麼可做的。 「讓主題 2.1 更簡潔，並加入一個真實世界的例子」會做到。
